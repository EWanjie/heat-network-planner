# Границы применения

**Модель.** Двумерный режим по техническому приложению. Расчёт по глубине (дополнительная задача) не реализован. Реконструкция
существующей сети и `tie_in` не используются (устарели). Рельеф не учитывается.

**Ограничения.** Учитываются типы из таблицы 2: `oks`, `park`, `social_area`, `prohibited_site`, `water`, `railway`, `road`, `tram_tracks`,
`gas_pipeline`, `power_cable`, существующая теплосеть. Другие типы игнорируются с записью в диагностике.
- Газопровод, кабель и чужая теплосеть пересечению не подлежат: специальный интервал ±2 м короче требуемого отступа, поэтому такое
  пересечение считается конфликтом правил (запрошено уточнение у организаторов).
- Дороги OpenStreetMap без ширины в основных вариантах не учитываются; в дополнительных принимаются по классу (магистральные и городские).

**Параметры проекта, которых нет в приложении:** наименьший угол подхода к линии врезки 45°; вычислительный запас 0,75 м при поиске
(итоговые отступы проверяются точно).

**Поиск эвристический.** «Маршрут не найден» — «алгоритм не нашёл в пределах рабочей области, числа шагов и времени», а не доказательство.
Оптимальность сети не гарантируется: варианты — результат жадного построения с улучшением.

**Ресурсы.** Расчёт одного файла занимает до ~2 ГБ памяти и на данных ЗИЛ около 3 минут (первый расчёт файла) и около 1,5 минуты
(повторный). Ограничения читаются потоком и хранятся только в рабочей области (600 м вокруг сети и точек); проверка уникальности id хранит
64-битные хэши, а не строки. Файл **3,19 ГБ (12,5 млн объектов)** обработан при лимите памяти Java 1 ГБ: проверка загрузки 98 с,
полный расчёт 262 с, результат тот же, что на исходных данных. Одновременно идёт один расчёт, остальные ждут в очереди (до 50 заданий).

**Данные.** Хотя бы одна точка подключения и участок существующей сети; координаты WGS 84; проверка структуры, геометрии, обязательных
атрибутов и уникальности id выполняется при загрузке, замечания к данным выводятся в диагностике.
