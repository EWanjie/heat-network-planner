# Моделирование трасс подключения к тепловым сетям

Прототип команды **«Контора»** для задачи № 2 ЛЦТ 2026.

Сервис принимает GeoJSON территории, ищет схемы подключения зданий к существующей теплосети, подбирает диаметры труб и рассчитывает стоимость строительства. Найденные варианты отображаются на карте и доступны для выгрузки в GeoJSON.

## Возможности

- Загрузка и проверка одного GeoJSON-файла.
- Отображение зданий, существующей теплосети, точек подключения и ограничений.
- Поиск допустимых трасс с учётом препятствий и необходимых отступов.
- Формирование общих участков сети для нескольких потребителей.
- Подбор диаметров по суммарному расходу и допустимой длине.
- Расчёт стоимости трубопроводов, камер и врезок.
- Проверка геометрии, топологии и расчётных параметров перед выдачей результата.
- Отображение до трёх найденных вариантов на отдельных вкладках.
- Выгрузка выбранного решения в GeoJSON.

> В текущей версии расчёт использует только объекты загруженного файла. Автоматическая загрузка дорог OSM и внешняя картографическая подложка отключены. Если дороги и коммуникации отсутствуют в исходных данных, они не участвуют в расчёте.

## Сценарий использования

1. Откройте стартовую страницу.
2. Выберите или перетащите один файл `.geojson` либо `.json`.
3. Дождитесь проверки файла.
4. Расчёт начнётся автоматически. На экране ожидания отображаются прошедшее время и кнопка отмены.
5. Если найден хотя бы один проверенный вариант, откроется страница результатов.
6. Во вкладке **«Исходные данные»** доступны карта и состав загруженного набора.
7. Во вкладках **«Решение»** или **«Решение 1», «Решение 2», «Решение 3»** отображаются найденные схемы и расчётные показатели.
8. Выберите вариант и нажмите **«Выгрузить данные»**, чтобы скачать GeoJSON.

Слои карты можно включать и отключать в легенде. Нажатие на объект открывает его атрибуты.

Если проверенных вариантов нет, приложение предлагает повторить расчёт или выбрать другой файл. Отсутствие результата не доказывает невозможность подключения.

### Время расчёта

Интерфейс передаёт серверу следующие ограничения поиска:

- до 30 секунд;
- до 30 000 расширений графа.

Финальная проверка и передача результата могут потребовать дополнительного времени. Если сервер не отвечает в течение 60 секунд, интерфейс прекращает ожидание и отправляет запрос отмены.

Повторный запуск с теми же данными не гарантирует улучшения результата.

## Входные данные

Ожидается GeoJSON типа `FeatureCollection` с массивом `features`.

Координаты задаются в **WGS 84 / EPSG:4326**, порядок:

```text
[долгота, широта]
```

Для каждого объекта обязательны:

- корректная непустая `geometry`;
- `properties.id` — уникальный строковый или числовой идентификатор;
- `properties.object_type` — тип объекта.

Числовой идентификатор `1` и строковый `"1"` различаются.

### Основные типы объектов

| Объект | `object_type` | Требования |
|---|---|---|
| Существующий трубопровод | `heat_network` | `LineString`, поле `diameter` |
| Тепловая камера | `heat_chamber` | `Point` |
| Точка подключения здания | `oks_connection_point` | `Point`, положительный числовой `flow_tph` |
| Существующее здание | `oks_existing` | `Polygon` или `MultiPolygon` |
| Источник теплоснабжения | `source` | Обычно `Point` |
| Ограничение | `restriction` | Дополнительное поле `restriction_type` |

`flow_tph` задаёт расход теплоносителя в тоннах в час. Он должен находиться непосредственно у точки подключения. Расход, указанный только у связанного здания, его не заменяет.

Для поиска подключения необходим хотя бы один существующий трубопровод.

### Типы ограничений

Поддерживаемые значения `restriction_type`:

```text
oks
park
social_area
prohibited_site
water
railway
road
tram_tracks
gas_pipeline
power_cable
heat_network
```

Для линейных дорог и трамвайных путей требуется известная ширина `width_m`. Значение `width_source: "unknown"` означает, что ширина не подтверждена.

Неизвестную ширину алгоритм не заменяет произвольным значением. Неподдерживаемые типы ограничений не игнорируются молча.

### Диаметры труб

Поддерживаемые значения `diameter`, мм:

```text
50, 65, 80, 100, 125, 150, 200, 250, 300,
400, 500, 600, 700, 800, 900, 1000, 1200, 1400
```

Сохраните следующий текст в файл `demo.geojson` и загрузите его в приложение:

## Алгоритм

### 1. Подготовка геометрии

Сервис читает GeoJSON, преобразует координаты в метрическую систему EPSG:32637 и строит пространственный индекс объектов.

### 2. Учёт ограничений

Для объектов определяются необходимые отступы с учётом габаритов пары труб. Для специальных пересечений применяются отдельные правила и коэффициенты стоимости.

### 3. Поиск маршрутов

Алгоритм строит разреженный граф видимости и использует направленный поиск A*. Проверяются разные точки врезки и подходы к потребителям.

### 4. Формирование сети

Рассматриваются отдельные подключения и общие участки с узлами ответвления. Для общих участков пересчитываются суммарные расходы и диаметры.

### 5. Отбор вариантов

Среди найденных проверенных схем сначала сохраняются варианты с наибольшим числом подключений. Затем учитываются стоимость, длина и различия между схемами.

Приложение выдаёт до трёх вариантов. Разные стратегии могут привести к похожим схемам, поэтому итоговых вариантов может быть меньше трёх.

### 6. Проверка результата

Проверяются:

- топология сети;
- расходы и пропускная способность;
- диаметры и допустимые длины;
- геометрия трасс и ограничения территории;
- расчёт стоимости.

После формирования GeoJSON отдельный валидатор повторно проверяет экспортируемые данные.

> Поиск ограничен временем и числом шагов. Глобальный оптимум и подключение всех объектов не гарантируются.

## Результат расчёта

Каждое решение выгружается как GeoJSON `FeatureCollection`.

В состав результата могут входить:

- новые участки теплосети;
- новые камеры;
- технические узлы;
- сводка `variant_summary`.

Объект сводки имеет `geometry: null`.

Экспорт описывает рассчитанную сеть и не является полной копией исходного файла. Сохраняйте исходный GeoJSON вместе с результатом: ссылки на существующие объекты используют их первоначальные идентификаторы.

### Показатели

| Поле | Описание |
|---|---|
| `construction_cost` | Стоимость строительства с учётом камер и врезок, ₽ |
| `chamber_construction_cost` | Стоимость камер, уже включённая в строительство, ₽ |
| `existing_chamber_tie_in_count` | Число врезок в существующие камеры |
| `existing_chamber_tie_in_cost` | Стоимость этих врезок, уже включённая в строительство, ₽ |
| `new_network_length` | Протяжённость новой сети, м |
| `unconnected_oks_ids` | Идентификаторы неподключённых точек |
| `unconnected_penalty` | Расчётный штраф за неподключённые точки, ₽ |
| `calculated_cost` | Стоимость строительства плюс расчётный штраф, ₽ |
| `score` | Значение критерия S |

Формула оценки, реализованная в текущем коде:

```text
S = 0,7 × calculated_cost / 25 000 000
  + 0,3 × new_network_length / 100
```

Меньшее значение S предпочтительнее при сравнении вариантов.

**Важно:**

- расчётный штраф является компонентом оценки, а не фактической строительной работой;
- стоимость камер и врезок уже включена в `construction_cost`;
- длина и погонные расценки относятся к паре труб и не удваиваются;
- статус `validation_status: "VALID"` означает прохождение реализованных проверок, а не инженерную экспертизу.

## API

Базовый адрес при локальном запуске:

```text
http://localhost:8080
```

| Метод | Адрес | Назначение |
|---|---|---|
| `POST` | `/api/upload` | Загрузка и проверка файла |
| `POST` | `/api/plan` | Синхронный расчёт схем подключения |
| `DELETE` | `/api/plan/{requestId}` | Запрос отмены активного расчёта |

### Загрузка файла

`POST /api/upload`

Тип запроса: `multipart/form-data`.

Поле формы: `file`. Необходимо передать ровно один файл.

Успешный ответ содержит статистическую сводку загруженных данных.

### Расчёт

`POST /api/plan`

Тип запроса: `application/json`.

```json
{
  "requestId": "demo-request-001",
  "dataset": {
    "type": "FeatureCollection",
    "features": []
  },
  "osm": {
    "required": false,
    "status": "disabled"
  },
  "options": {
    "maxTimeMillis": 30000,
    "totalSearchBudget": 30000
  }
}
```

Замените `dataset` содержимым входного GeoJSON. Пустой массив в примере показывает структуру запроса, но не представляет задачу для расчёта.

`requestId` должен быть уникальным для активного запроса и состоять из 8–80 латинских букв, цифр или дефисов.

Ответ содержит:

- `variants` — найденные проверенные варианты;
- `diagnostics.issues` — диагностические сообщения;
- `searchStatistics` — время и статистику поиска.

Сервер выполняет один расчёт одновременно. При попытке запустить второй возвращается HTTP `429`.

Без явного задания `options` сервер использует лимиты 120 секунд и 250 000 расширений. Интерфейс приложения передаёт меньшие лимиты: 30 секунд и 30 000 расширений.

### Отмена

`DELETE /api/plan/{requestId}`

Запрос устанавливает флаг отмены, который проверяет алгоритм. Остановка не является мгновенным завершением процесса.

## Ограничения текущей версии

- Расчёт выполняется по загруженному набору данных. Дополнительные дороги и коммуникации автоматически не загружаются.
- Используется фиксированная проекция EPSG:32637. Работа с другими географическими зонами требует настройки и проверки.
- Модель двумерная. Глубины прокладки в экспортируемых участках оставлены `null`.
- Возможны частичные результаты и отсутствие найденной схемы.
- Каталог диаметров, расценок и ограничений зафиксирован в коде.
- Карта не отображает файлы больше 100 МиБ.
- Настроенный HTTP-лимит загрузки 3 ГБ не означает поддержку расчёта для файлов такого размера. При обработке и отображении данные размещаются в памяти.
- Серверная база проектов, очередь фоновых заданий и встроенный Swagger UI не реализованы.
- При перезагрузке страницы результатов приложение возвращается к загрузке. Для сохранения нужного варианта используйте выгрузку GeoJSON.

Прототип предназначен для предварительного моделирования. Полученные схемы требуют проверки специалистами перед использованием в проектировании.

## Возможные проблемы

| Проблема | Решение |
|---|---|
| Команда `mvn` не найдена | Установите Maven и добавьте его в PATH либо используйте Maven в IDEA |
| Приложение не запускается | Проверьте JDK 11, загрузку зависимостей и журнал запуска |
| Порт 8080 занят | Остановите другой экземпляр или выберите другой порт |
| После обновления отображается старый интерфейс | Перезапустите приложение и обновите страницу через `Ctrl+F5` |
| Файл не проходит проверку | Проверьте структуру GeoJSON, идентификаторы, геометрию и обязательные поля |
| HTTP 429 | Дождитесь завершения предыдущего расчёта или запросите его отмену |
| Решение не найдено | Проверьте данные и ограничения; при обращении к API изучите `diagnostics.issues` |
| Maven сообщает об отказе доступа к `target` | Проверьте права на папку проекта и блокировку файлов другими процессами |
