# Сервис моделирования трасс подключения к тепловым сетям

Кейс «Лидеры цифровой трансформации» 2026, Департамент информационных технологий города Москвы.
Java 11, Spring Boot 2.6.3, Maven. Правила расчёта берутся из **актуального технического приложения** и
«Разъяснений по вопросам ЛЦТ»; при расхождении с общим ТЗ (PDF) действуют они.

## Что делает сервис

Из одного GeoJSON строит до трёх существенно разных вариантов подключения перспективных точек ОКС к существующей
тепловой сети (двумерный режим): трассы, тепловые камеры, диаметры, стоимость, показатель S. Результат показывается
на карте и выгружается в GeoJSON по разделу 7 приложения.

| Часть | Что делает | Где |
|---|---|---|
| Загрузка и проверка файла | Потоковое чтение GeoJSON, проверка структуры, геометрии, типов, обязательных атрибутов, уникальности id (`"1"` и `1` — разные), диагностика данных | `GeoJsonInspector`, `UploadController`, `ExistingNetworkBuilder` |
| Правила и отступы | Таблицы 1–2 приложения как данные; запретные зоны по ДУ на JTS (отступ + половина габарита + половина ширины пары труб) | `Rules`, `RuleSet`, `ObstacleSet` |
| Поиск одной трассы | Граф видимости + A* с состоянием направления, поворот не более 90°, предельная длина ДУ, атомарный специальный проход через дорогу (полоса + 3 м, угол не менее 45°, K = 1,60) | `Router`, `Start`, `Goal` |
| Подход к зданию | Один финальный прямой участок от ближайшей к точке границы; если он невозможен — причина отказа (двор, выемка, чужая зона) | `Start` |
| Совместное подключение | Цели добавляются в дерево: к существующей сети или к уже построенной ветви; в узле новой сети до четырёх примыкающих участков (ствол даёт два, ветвей до двух) | `JointPlanner`, `Branch` |
| Диаметры и стоимость | Расход участка — сумма ниже по течению; ДУ не убывает к сети; предельная длина непрерывной части одного ДУ; камеры, врезки, штраф, S | `TreeEvaluator` |
| Улучшение | Перепривязка концевых ветвей и перестройка цепочек с принятием только при улучшении S | `JointPlanner.improve`, `rebuildChains` |
| Варианты | Несколько стратегий (порядок целей × показатель поиска), отбор существенно разных (не менее четверти ветвей с другой врезкой) | `Variants` |
| Валидатор | Независимая проверка трасс и дерева: отступы прямым расстоянием JTS, углы, повороты, расходы, длины, узлы, структура | `PlanValidator` |
| Выгрузка | `heat_network`, `heat_chamber`, `technical_node`, `variant_summary`; узлы по id, концы участков совпадают с узлами | `OutputBuilder`, `/api/plan/export` |
| Интерфейс | Карта OpenLayers; вкладки «Решение 1–3», «Доп. вариант 1–3», «Было 1–3»; список точек, проверка результата, причины отказов | `static/`, `plan-view.js` |
| Дороги OpenStreetMap | Оси дорог для области данных передаются в расчёт; в основных вариантах учитываются дороги с шириной, в дополнительных — магистральные и городские по классу | `road-enrichment.js`, `PlanInput` |

## Основные и дополнительные варианты

- **Основные варианты** строго по данным файла и правилам приложения. Если к точке нельзя подойти по правилу
  (ближайшая граница здания во дворе, в выемке или её выход в чужой зоне отступа), точка остаётся неподключённой,
  причина показывается в списке, штраф входит в стоимость.
- **Дополнительные варианты** (фильтр «Дополнительные варианты») строятся с допущениями и всегда их перечисляют:
  подход к ближайшей допустимой границе здания — только для тех зданий, к которым по правилу подойти нельзя;
  ширина дорог OpenStreetMap без ширины принимается по классу. В выгрузку они попадают только при включённом фильтре.
- **Прежние версии** (фильтр «Прежние версии») — структура сети до перестройки цепочек для сравнения; в решении
  включается пунктирным слоем.

## Ограничения и допущения проекта

- Подход к линии врезки под острым углом не менее 45° — параметр проекта, в приложении числа нет.
- Пересечение газопровода, кабеля и чужой теплосети запрещено: специальный интервал ±2 м короче требуемого отступа.
- Поиск эвристический: «маршрут не найден» означает «алгоритм не нашёл», а не доказательство отсутствия.
- Число меток одного поиска ограничено; расчёт идёт по одному файлу за раз; вся геометрия хранится в памяти
  (для файлов в гигабайты нужна временная база).
- Первый расчёт файла занимает около трёх минут (на данных ЗИЛ), повторный около полутора: графы видимости
  строятся при первом обращении и переиспользуются.

## Платформа и требования конкурса

| Требование | Состояние |
|---|---|
| Java 11, Spring Boot 2.6.3 | выполнено |
| PostgreSQL (до 18) как основная база | задания и результаты хранятся в базе через JPA; PostgreSQL 16 в `docker-compose.yml`, H2-файл для локального запуска |
| Swagger UI, springdoc-openapi-ui 1.7.0 | `http://localhost:8080/swagger-ui.html` |
| docker-compose 1.29.2 | `Dockerfile` и `docker-compose.yml` (спецификация Compose без ключа `version`); конфигурация разобрана, запуск контейнеров на этом компьютере не проверялся (нет WSL), проверьте на Ubuntu |
| Ubuntu Server 22, ОЗУ 16 ГБ | образ на Java 11, память Java задаётся `JAVA_OPTS` |
| Файл до 3 ГБ, потоковая обработка | загрузка потоком на диск; ограничения читаются потоком и хранятся только в рабочей области; проверено на файле 3,19 ГБ (12,5 млн объектов) при лимите памяти 1 ГБ: проверка загрузки 98 с, расчёт 262 с |
| Выгрузка до 500 МБ | результат хранится в базе как текст |
| До 50 пользователей | асинхронные задания, очередь до 50, один расчёт одновременно |

## Запуск

```
docker-compose up --build
```

или локально:

```
mvn clean package
java -jar target/heat-network-planner-1.0-SNAPSHOT.jar
```

Страница: http://localhost:8080 (порт можно сменить `--server.port=8090`). Загрузите GeoJSON, откройте вкладку
«Решение 1» и дождитесь расчёта (прогресс и очередь показываются в панели слева).
## Проверки

Тесты: `mvn test` (правила и геометрия, поиск, дерево и диаметры, валидатор, выгрузка, чтение по рабочей области, сквозные сценарии
с примером из ТЗ, дорогой, газопроводом, парком, водой и двором здания).
Тестовые файлы лежат в `test-data/`; ожидаемый результат по каждому записан в `scripts/check-test-data.ps1`.
При работающем сервисе:

```
powershell -File scripts\check-test-data.ps1 -Base http://localhost:8080
node src\test\js\road-enrichment.test.cjs
```
